## Рекомендации для согласования

1. **P2, pruning партиций:** добавить к текущему tuple-курсору эквивалентное `created_at <= cursor_created`. Сам tuple `< (created_at,id)` оставить: замена на строгое `< cursor_created` теряет строки с тем же временем и меньшим id. На том же PG16 сравнение исключило три будущие месячные партиции активности и будущую годовую партицию комментариев. DEFAULT остаётся, поскольку может содержать более старые даты. Страница полностью совпала в обоих вариантах. [Скрипт](review-db-tasks-2026-11-23-evidence/compare_pruning.py), [планы/проверка совпадения](review-db-tasks-2026-11-23-evidence/partition-pruning-pg16.txt). Существующие тесты проверяют курсорную пагинацию; отдельную регрессию с одинаковыми timestamp для предлагаемого предиката нужно добавить после согласования. Backend не менялся.
2. **P3, tiebreak-индексы:** если большие пользовательские списки/темы покажут нагрузочную проблему, отдельно измерить индексы с завершающими anime_id/id и вариант списка без status. На seed текущий Sort/Incremental Sort дёшев; добавлять все такие индексы сейчас не обосновано. Индексы партиционированных таблиц проектировать с учётом дочерних индексов и стоимости записи.
3. **Offset:** список, отзывы и темы остаются offset-пагинацией по контракту. Глубокие страницы оценивать на большом наборе, не менять контракт молча.
